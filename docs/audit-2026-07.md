# agent-kit production-readiness audit — 2026-07-26

A multi-agent audit of this repository against six stated goals, and the roadmap it produced.
Every finding below was raised by one agent and then independently re-verified by a second
agent that opened the cited files and, where possible, executed the code. Findings that could
not be verified were dropped.

## The six goals audited against

| | Goal |
|---|---|
| A | Production-grade open source usable by a large engineering team |
| B | Extensible and multimodal across any operating system |
| C | Accurate skills and workflows for many providers |
| D | Memory management via Obsidian + Qdrant + Graphiti |
| E | Cutting-edge hot-data to cold-data storage and lifecycle flows |
| F | Evaluation of whether skills and workflows improve over time, in accuracy and in return on code churn |

## Method

Three workflows, 41 agents:

1. **Internal audit** — ten dimensions audited in parallel, each finding then attacked by an
   adversarial verifier instructed to default to REFUTED when it could not reproduce the claim.
   The verifiers also hunted for what the auditors missed, contributing 51 findings of their own.
2. **External benchmark** — five parallel research sweeps over prior art (agent memory systems,
   retrieval and tiering, skill-portability standards, agent evaluation, OSS productization),
   followed by a completeness critic that killed 16 recommendations and caught a fabricated
   citation in the research itself.
3. **Synthesis** — three independently-framed roadmap architects, three judges scoring on
   distinct lenses, then a synthesizer, then per-milestone authoring.

### Confidence and its limits

- **0 findings were refuted**, but 68 were *revised* — severity corrected, evidence extended, or
  the recommendation rewritten. Treat REVISED findings as verified in substance, not in wording.
- The **shippability judge failed** its structured-output retries, so the lens checking milestone
  sizing did not run in the workflow. It was applied manually afterwards; the direct consequence
  was splitting the original 45-issue M8 into M8 and M9.
- One architect proposal and several agent claims about counts were corrected against the repo.
  Where this report states a number, it was measured, not asserted.

## What is already good, and should not be broken

- `workspace-tooling/path_contract.py` is the one module written for relocation on purpose: symbolic `${PERSONAL_WORKSPACE_ROOT}` / `${PERSONAL_VAULT_ROOT}` tokens, `pathlib` + `os.path.expanduser/abspath`, no string concatenation, and it imports and runs clean on Windows. It is the correct model for the rest of the tree.
- The OS feature-detection idiom already exists in-repo and is correct where used: `getattr(os, "O_CLOEXEC", 0)`, `getattr(os, "O_NOFOLLOW", 0)`, `getattr(os, "O_DIRECTORY", 0)` in `artifact_security.py:144-148,221-223` and `safe_vault_link.py:69-74`. The problem is inconsistent application, not an absent pattern.
- The catalog-as-single-source-of-truth design is right: `data/scripts/catalog-generate.py` derives everything from frontmatter and `--check` proves the catalog<->`data/` 1:1 correspondence (`claude_correspondence()` in generate-adapter-packs.py:430-467). Do not replace this with hand-maintained per-provider trees.
- The surgical per-field ref rewriting (`rewrite_refs`, generate-adapter-packs.py:125-159) with placeholder tolerance is a real improvement over the naive `claude`->`Codex` substitution it replaced, and the `_PLACEHOLDER_RE` distinction between rewritable-but-unverifiable templates and link-checkable targets is subtle and correct.
- `workspace-tooling/artifact_retrieval.py` is a real hybrid retriever, not a vector-only toy: FTS5 BM25 with per-column weights (line 39), dense candidates, RRF fusion at k=60, a cross-encoder rerank stage, per-artifact result caps, and duplicate-span suppression by IoU. Every ranking knob is enumerated in `ranking_contract()` (line 108) and digested, so a ranking change is detectable rather than silent.
- The catalog→outbox→index chain is hash-verified end to end. `artifact_memory._read_verified` (artifact_memory.py:114) re-opens with O_NOFOLLOW, re-hashes, and compares dev/ino/size/mtime before *and* after the read, refusing to return text that no longer matches the catalog revision. Treating the index as a discovery hint and the canonical Markdown as the authority is the correct layering and is enforced in code, not just documented.
- The fail-closed retention classifier in `artifact_outbox_retention.py` is genuinely excellent design: three independent, computable predicates (`state_bound`, `holds_irreproducible`, `manifest_named`), every uncertainty resolving to RETAIN, and a report-only contract. This is the correct *safety kernel* for a demotion engine — build tiering on top of it, do not replace it.
- `artifact_unit_archive.py:220-303` gets the hardest part of durability-before-deletion right: coverage is attested unit-by-unit against the live `sink_units` set, payload digests are re-validated (`_payload_intact`, :192-217), and the archiver and the retention classifier route through ONE shared `covered_revisions()` query so the two notions of 'preserved' can never diverge. That invariant is the thing a tiering system must preserve.
- workspace-tooling/artifact_retrieval_eval.py is a genuinely rigorous, publication-quality retrieval eval: dev/holdout split with a one-shot O_EXCL holdout ledger, four ranking modes, recall@10/MRR/nDCG/exact-citation/abstention metrics, per-category breakdowns, hard negatives, latency percentiles, and a gate that beats simple lexical+vector baselines by a declared factor.
- workspace-tooling/artifact_evidence.py is an excellent reusable primitive: every gate check records observed value, operator, threshold, and a verdict COMPUTED from those three, so evidence cannot record a verdict that contradicts its own bar. It is stdlib-only and should be the base of any future skill-eval gate.
- Licensing and third-party attribution are handled properly and unusually well: MIT LICENSE at the root, plus an explicit upstream credit for the transcribed ruflo (MIT) detection patterns at README.md:134-136 and in the header of src/security/aidefence-rules.ts, including a noted deliberate deviation. Do not let a cleanup pass drop that attribution.
- The four generator gates are real, machine-checkable, and return correct non-zero exit codes (verified: catalog-generate --check and generate-root-contract --check both exit 2 when dirty, generate-adapter-packs --check exits 0 clean over 48 files). The hard engineering for CI already exists; only the workflow YAML that invokes them is missing.
- The Python substrate's dependency layering is genuinely clean and acyclic: `artifact_security.py` (fan-in 23) → `artifact_runtime.py` (18) → `artifact_ingestion.py` (11) → everything else. Nothing imports upward. This is the right shape — it just needs to be made explicit and enforced by a package boundary rather than convention.
- `workspace-tooling/artifact_runtime.py` is a model config loader: `load_runtime()` schema-version-pins (SCHEMA_VERSION = 2), rejects unknown/missing fields with a field-level diff (`retrieval fields mismatch; missing=…, unknown=…`), validates every path for private ownership/mode, and refuses non-loopback Qdrant URLs. This is the pattern the rest of the repo's configuration should adopt.
- src/security/aidefence.ts is genuinely well-built: pure functions, zero runtime deps, NFKC+zero-width normalization, per-call RegExp cloning to dodge the stateful `lastIndex` footgun (line 113), and an explicit zero-width-match infinite-loop guard (line 124). Do not rewrite this.
- src/security/aidefence-rules.ts is patterns-as-data with every tightening pre-registered and justified (RULE_ADJUSTMENTS_NOTE, lines 63-87), plus an honest UNIMPLEMENTED_CATEGORIES list and a documented known-FN on JSON-escaped Windows paths (line 169). This level of self-honesty is rare and worth preserving.
- Test *depth* is genuinely strong for a one-person repo: 593 Python test methods across 37 modules, with real adversarial cases (torn-line concurrency under a fork pool, fail-closed hash mismatch, protocol-version fencing, redirect/content-type/2-MiB response bounds in src/tools/artifact-memory.test.ts).
- src/mcp-contract.test.ts is a well-designed golden contract test — it snapshots tools/list name+inputSchema only, deliberately excluding descriptions so prose edits don't red the gate, and spawns the real server over stdio against a hermetic fixture tree.
- `workspace-tooling/artifact_memory_provision.py` is a genuine plan/apply provisioner with a strictly read-only default, field-level config diffing, idempotent re-runs, and an explicit `--replace-runtime` gate — this is the right shape for the doctor/installer the rest of the repo lacks, and should be generalized rather than replaced.
- Dependency reproducibility is taken seriously: `workspace-tooling/requirements-artifact-ingestion.txt` (2 top-level pins) plus a 53-package `requirements-artifact-ingestion.lock.txt` with a provenance header, enforced by `lock_check.py` as a drift tripwire. The known limitation (version-pinned, not hash-pinned, because of per-platform wheels) is documented honestly rather than hidden.

## Headline findings

These were reproduced first-hand on a Windows machine, from source rather than from the
committed build:

1. **The README Quick Start does not start the server.** The documented command fails with
   `PLATFORM_ROOT environment variable is required` — a variable the README never mentions.
2. **The default profile crashes on Windows.** With `PLATFORM_ROOT` set, startup dies in
   `src/tools/artifact-memory.ts:177`, called eagerly from `createArtifactMemoryTools` (:380)
   via `src/index.ts:161`. Only `SERVER_PROFILE=shared` boots, and that profile deliberately
   drops the personal-memory tier and all four artifact-memory tools.
3. **The gates the README calls mandatory did not pass at HEAD.** Originally reported as two
   red gates (`catalog-generate` and `generate-root-contract`). **Corrected 2026-07-28:** only
   `catalog-generate` was genuinely red — a stale `data/facts/catalog.json`. The
   `generate-root-contract` failure was a **false** one, caused by non-UTF-8 console decoding
   on Windows: it passes under `PYTHONUTF8=1`. That is the encoding defect F-032/F-151/F-162
   describe, observed rather than inferred. `agent-kit doctor` sets `PYTHONUTF8=1` so it does
   not reproduce the false failure.
   **Resolved 2026-07-29:** the catalog was regenerated and all gates — now five, including
   the new `mcp-server-name-check` — pass. This does not close M2, which is about making the
   gates *enforced and platform-independent*, not merely green once.
4. **`data/skills/` contains exactly one skill.** Against 20 agents, 32 references and 5
   commands. Goal F — measuring whether skills improve — currently has a population of one,
   which is why the evaluation work is sequenced behind growing a corpus.
5. **The name collides with OpenAI AgentKit** (announced 2025-10-06). Every publishing task
   is blocked behind resolving it, so that decision is the first epic of the first milestone.

- **F038** — Shared team memory tier. - **F060, F061, F069, X046** — Cold-plane internals: content-addressed unit store, revision compaction, compressed/deduplicated archives and deliberate quantization. X048's own instruction is to instrument and measure for a month before building any of this, and M8 E3 ships exactly those instruments (the access ledger and per-class storage accounting with growth forecasting). Building a CAS and a quantization matrix for a corpu
- **F057, F065** — Partial scope, declared rather than silently halved. Both are scheduled in M8 E3 but not in full. F057 ships the gated point-eviction path and a configurable storage class — which is what F046's WARM demotion actually requires — but not the two-collection hot/cold matrix with per-tier quantization, which belongs with the deferred cold-plane block above. F065 ships rehydration resolving a revision 
- **X013** — MCP Skills Extension (SEP-2640). Differentiating and L, targeting a live draft PR whose SHA can move underneath an implementation. The correct trigger is already scheduled: X052's drift watchdog in M7 E2 pins the exact upstream revision and reports movement, so this can be picked up the moment the SEP stabilises rather than rewritten when it shifts.
- **X035** — Asynchronous consolidation as a supervised event-consumer job (importance, merge, decay, eviction as four legs). L effort duplicating in a more elaborate form what M8 E3's access ledger, decay policy and lifecycle jobs already deliver simply. Revisit once the ledger demonstrates real duplicate pressure and near-duplicate volume that the simpler path cannot absorb.
- **X040, X041, X045** — Seeded-defect calibration of the adversary metric, an N-by-N agent-triggering confusion matrix, and a cross-provider parity report. All three need the golden task set (M6 E4) and the per-provider runner (M7 E3) to exist and to have run for a release cycle before they have inputs. Note this is a sequencing deferral, not an n=1 one — X041's population of 20 agents is real and its triggering has simp
- **X047** — AST-aware chunking for code artifacts. The heading-aware half is already delivered by F047's per-artifact-type chunk profiles in M8 E1. The AST half pulls tree-sitter into an ingest path whose entire value proposition is being dependency-free, deterministic and hash-verified, to chunk a corpus that is almost entirely prose — the kit does not ingest a code corpus today.
- **X053** — Extracting the compiler as a standalone interop package. Its own recommendation says 'last, not first', it is XL, and it would fork the maintenance burden of a project that at that point has had one green CI run.
